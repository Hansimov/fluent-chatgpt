# 浏览器回归测试

在项目目录执行：

```cmd
node tests/run-browser-tests.cjs
node tests/run-startup-tests.cjs
```

需要 Node.js 18+ 和 Chrome / Chromium。若无法自动找到浏览器，可通过 `CHROME_PATH` 指定可执行文件。

测试使用独立的临时浏览器配置，以 headless 模式运行，不连接账号，也不会操作已打开的 Chrome 窗口。临时配置在运行结束后删除。也可以直接在浏览器打开 `conversation-parsing.html` 查看逐项结果。

覆盖旧版消息结构、新版无 `main` 的 transcript、搜索单元及消息身份属性、`display:contents` 包装、`MarkdownRoot` 正文、读屏角色后备、新旧属性混合嵌套、隐藏/重复消息、章节和搜索、图片归属/标题/顺序、节点复用、反向滚动、API 分支映射与会话容器重新挂载。新版结构来自本机样本页的只读检查；测试使用合成内容，不保存私人会话或登录信息。

问答增量更新测试保留真实 MutationObserver、关闭定时巡检：覆盖旧 API 快照、虚拟化卸载历史消息、连续提交、正文补全、官方目录数量滞后、重复输入和临时消息补齐 ID。新问题应在无需刷新或网络请求的情况下保留绝对序号并追加；官方目录首次完整挂载时仍能纠正早期暂定编号。

`conversation-export.html` 覆盖新版无官方问答按钮、仅挂载尾部消息的导出：每批刷新一次结构化会话，按当前分支和消息 ID 补齐完整历史，校正选中项的暂定编号，并排除内部分析、工具调用和其他分支。测试还包括图片附件、未完成回答、接口离线后的 DOM 后备、局部失败、取消、路由切换和现代 MarkdownRoot 的正文选择。实际执行 Markdown / ZIP 导出入口，在内存中截获并解析 ZIP，检查 Markdown、HTML、问答顺序及失败清单，不向用户下载目录写文件。

未挂载回答保留结构化数据中的原始 Markdown；HTML 归档安全转义并按原文换行显示。已挂载且消息 ID 一致的回答保留网页排版。导出不会为了历史正文滚动新版会话，也不会点击附件或触发 ChatGPT 的其他操作。

## Markdown 图片和附件（4.8.0）

勾选“图片和附件”后点击“全部 MD”或“选中 MD”：支持目录写入的浏览器会先询问保存位置，随后在所选位置创建全新的归档子目录，保存 `.md`、`assets/q001/…` 和 `manifest.json`。重复导出不会覆盖已有文件。浏览器或油猴隔离环境不支持目录写入时，下载只含 Markdown 与附件的 ZIP，解压后即可通过相对路径离线查看。取消目录选择不会启动下载；取消写入时保留已经完成的文件。不勾选“图片和附件”仍导出单个 `.md`。

结构化消息中的 `image_asset_pointer` 按原顺序嵌入用户/回答正文；只有旧版 `metadata.attachments` 的图片补在对应角色的消息下，普通文件使用链接。历史图片不要求先在网页加载。保留原生 Markdown 表格、代码缩进，并通过文件 ID 去重、为并发下载预分配稳定编号。缺失/过期附件不冒用同名文件，清单记录失败原因。

`markdown-assets.html` 使用合成的旧版 `sediment://` 上传图、同名文件、图片回答、PDF 和表格，模拟目录句柄（不写用户磁盘）并实际生成/解析 ZIP，逐项检查本地引用、目录隔离、重复导出、取消、权限后备与失败清单。通过 `run-realtime-tests.cjs` 运行：Blob 异步 I/O 不能可靠地用 Chrome 虚拟时间驱动。

`navigation-jump.html` 模拟不等高的 50 轮虚拟列表（只挂载邻近几轮，没有旧版导航按钮），检查历史定位、反向滚动、偏移量、共享外层误标、节点复用、连续点击和用户滚动取消。目录定位按消息 ID 和当前挂载位置逐步查找，图片布局变化后重新校正；读取会话快照后即补齐历史目录。

单独运行一个夹具：`node tests/run-browser-tests.cjs markdown-assets.html` 或 `node tests/run-browser-tests.cjs navigation-jump.html`。

### 导出完整性修复（4.8.1）

用户消息中的图片和附件直接内嵌或以普通链接呈现，不再额外添加“图片、附件与 Artifacts”标题；已经在正文中的资源不重复列出。`library_file_id` 是资源库引用，不作为另一份文件下载。没有最终回答的问答也会保留完整用户输入和上传附件，并在正文及清单中注明缺少最终回答，不能因回答为空而丢弃上传图。

`safe_urls` 白名单、搜索结果和普通网页引用不作为附件批量抓取；原生引用标记转换为可点击的 Markdown 来源链接。正文明确提供的文件链接仍可下载。纯 `utm_*` 参数不会导致同一文件重复下载，文件 ID、版本参数与签名身份仍独立检查。真实下载失败会显示文字说明，不冒用其它文件，也不以破图图标代替错误信息。

文件连接等待上限调整为 8 秒；超时、临时网络错误及 408/429/5xx 最多重试一次，并重新获取文件元数据。单个文件的 403/404/过期或网络超时不会禁用其它文件的下载端点；明确不支持的端点仍可熔断。临时失败不写入失败缓存，取消信号可打断重试。

每批导出使用同一快照的正文与附件，导航触发的迟到 API 响应不能替换导出内容。下载附件期间可以继续点击问答导航；仅在 API 不可用、需要滚动挂载正文的 DOM 后备采集阶段暂存最后一次导航请求，采集结束后定位。用户主动导航后不再恢复旧滚动位置；切换会话会清除待执行导航。

`markdown-assets.html` 增加上述结构、失败重试、取消、未回答的上传、引用转换、导航期间 DOM 重挂载、迟到快照与旧页面延迟导航测试。测试只使用合成数据；本机导出审计与 Chrome 调试脚本保存在被忽略的 `.codex-*` 文件中，不提交私人会话、文件或登录信息。

`run-browser-tests.cjs` 同时检查标签栏在 160–560px 宽度、普通/大计数、不同可见标签数量下保持单行和双字全名，压缩按钮及标签栏两侧留白，并验证字体不小于 11px。极窄按钮暂时隐藏计数徽标（悬浮提示和辅助名称仍保留完整计数），宽度恢复或可见标签减少后自动恢复；正常面板宽度下计数保持可见。选区测试覆盖旧版 popover、新版正文 SelectionOverlay、输入框 Radix 格式工具条、缩放包装和延迟挂载，并确认选择/复制/输入、附件、模型菜单和图片控件不受影响。可分别打开 `navigation-tabs.html`、`selection-actions.html` 查看夹具结果。

导航标题悬浮提示和宿主节点的 `data-script-version` 显示实际运行版本。项目文件更新不会自动替换已经运行的标签页脚本；需更新油猴中的脚本并刷新标签页。

`run-browser-tests.cjs` 还会运行 `run-appearance-tests.cjs`：在独立的本地测试页中切换 `data-theme`、旧版主题 class、`color-scheme` 和系统主题，检查五种导航视图、选中/悬浮/键盘焦点以及折叠控件的配色。包含旧颜色变量缺失或冲突的情况；文字在纯黑/纯白底层内容上均检查对比度，选中背景则限制明暗差，避免深色模式出现刺眼白块。新版主题标记和变量名称来自本机样本页的只读检查。

同一测试使用真实 iframe 视口 resize 事件验证：窗口缩小后的临时限位、恢复原始位置/尺寸、折叠边缘锚点、缩小期间刷新、重新拖动，以及 body 重建后的主题切换。此测试不用虚拟时间（它不能可靠驱动 resize/动画帧），通过本地流式 HTML 等待检查结束，不操作用户的浏览器窗口。可单独运行 `node tests/run-appearance-tests.cjs`；追加 `dark` 或 `light` 会将预览截图保存到已忽略的 `.codex-navigation-*.png`。

布局检查也覆盖问答编号栏按实际位数分配宽度、多位编号与归档标记不重叠、问答/导出文本对齐，以及 H2 开头的回答从首级缩进开始、子章节仍保留层级关系。

`run-startup-tests.cjs` 额外启动仅监听 `127.0.0.1` 随机端口的测试服务器：保持 HTML 响应未完成，确认面板和问答/章节能在 `DOMContentLoaded` 之前出现。再验证延迟挂载、连续流式更新、动画帧暂停、路由检查延后、路由等待上限、旧会话隔离、分支/新建会话复用消息、面板被移除、main/body 重建，以及空白首页。API 请求在夹具中故意保持 pending，证明导航不依赖网络元数据完成。测试结束关闭服务器并删除临时 Chrome 配置，不访问真实会话。
